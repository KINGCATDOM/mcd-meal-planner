# 麦当劳点单决策助手（MCD Meal Planner）

> 一句话说清"今天麦当劳怎么点"，它把**门店、菜单、券、价格**全算完，交给你一个能直接下单的方案。

**🔗 在线演示**：https://mcd-order-helper-04958.app.workbuddy.host/?sharecode=BZK4BDOZRV


基于麦当劳官方 MCP 服务开发的 AI Skill，覆盖七个正经场景（**套餐推荐、麦门省钱、聚餐一键点、控卡口味配餐、活动新品雷达、券积分管家、节日场合搭配**），外加两个**要点名才给**的彩蛋：**麦门挑战套餐**和**麦门网红吃法**。

> 安装与使用步骤见 [使用说明.md](使用说明.md)

---

## 解决什么问题

在麦当劳点餐，真正的决策成本不在"选哪个汉堡"，而在这些碎事：

- 110 个单品、14 个品类，翻完菜单就饱了，最后还是点老样子
- 想点最便宜，但要比"单品 / 套餐 / 券 / 满减"四种组合
- 4 个人吃，点 3 份还是 4 份？人均多少？会不会浪费
- 为了凑满减硬加一份，结果**多花钱只多吃了一份薯条**
- 在减脂，但菜单上不写热量，套餐更是查不到
- 活动页天天喊"上新"，却不说这个新品值不值得试
- 券躺在卡包里，不知道哪张下周就过期
- 情人节/生日想点点仪式感，但麦当劳没有蛋糕也没有月饼

这些事**单独做都不难，一起做就很烦**。每次要翻 5 个页面，最后还是凭感觉点单。

这个 Skill 把它们合成一条链路：**你说需求 → 它调接口 → 你看到方案 → 你说"就这个" → 它下单**。

## 七个场景

| 场景 | 你说 | 它做 |
|---|---|---|
| **S1 套餐推荐** | "今天吃什么""帮我推荐一个" | 3 个不同风格的方案（经典/超值/尝鲜），每个给一句具体理由 |
| **S2 麦门省钱** | "一个汉堡加杯可乐，怎么点最便宜" | 三档方案（最省/最均衡/最满足）+ 省在哪张券 + **凑单陷阱检测** |
| **S3 聚餐一键点** | "4 个人吃，预算 160，有人不吃辣" | 按人数配量（不多点）、避开忌口、算人均、提示可加什么 |
| **S4 控卡口味配餐**（需点名） | "500 大卡以内怎么点""多少卡" | 热量预算内的组合 + 每项 kcal/蛋白/钠 + **同轮零成本替换** |
| **S5 活动新品雷达** | "最近有什么活动""这个值得尝吗" | 当季活动 + 哪些真值得试 + 现在能不能用 |
| **S6 券积分管家** | "我的券要过期了吗" | 券的生效时间表 + 积分到期提醒 + 用券顺序 |
| **S7 节日 & 场合搭配** | "情人节怎么点""生日怎么点""中秋吃点什么" | 按场合逻辑配餐 + 份量结构 + 场合适配理由 |
| **S8 麦门挑战**（需点名） | "不知道吃什么""来个挑战""整活" | 10 种趣味组合 + 吐槽 + 翻车提醒 |
| **S9 网红吃法**（需点名） | "隐藏吃法""网红吃法""怎么吃更好吃" | 网络流传吃法 + 流传度 + 哪些真值得试 |

七个场景共享同一条调用链，差别只在约束条件和输出侧重。

## 两个彩蛋，但要点名才给

**S8 麦门挑战**和 **S9 网红吃法**不会主动出现。你说"今天吃什么""帮我点"，它们一句都不会提。

只有你明确说这些词才触发：

- **挑战**：`不知道吃什么`、`挑战`、`整活`、`来点狠的`、`黑暗料理`
- **网红吃法**：`隐藏吃法`、`网红吃法`、`怎么吃更好吃`、`DIY`、`混搭`

**为什么藏起来**：正常点单的人只想知道点什么、多少钱。突然冒出一个"要不要挑战碳水爆炸"，是打扰，不是幽默。

例外是「不知道吃什么」——这时它会先给 **1 个**挑战方案破冰，再问你要不要正经推荐。**只给整活方案就走人，是不负责的。**

## 一个刻意的性能设计：热量默认关闭

**你不问热量，它就不算、不提、不输出。**

只有你主动说出「热量 / 卡路里 / 大卡 / kcal / 减脂 / 减肥 / 控卡 / 健身 / 增肌 / 多少卡」，才会去拉营养表。

原因很实际：`list-nutrition-foods` 单次返回 1.6 万字符（160 条全量数据），加上逐项匹配、套餐拆轮累加，能占掉整单三分之一的时间。**不减肥的人不该为这个功能付时间成本。**

所以点一份聚餐套餐时，你看到的只有价格，不会有一堆用不上的 kcal 数字。

## 一个必须先做的事：先比套餐，再看单品

**你不需要说"套餐"两个字，它也会先比套餐。**

很多人点麦当劳只算过"单品加在一起多少钱"，没算过"同样的东西走套餐多少钱"。实测同一顿饭：

| 路线 | 构成 | 实付 |
|---|---|---|
| 单品单点 | 板烧鸡腿堡 23.5 + 玉米杯 13 + 纯悦 7.5 | **¥44.00** |
| 套餐换项 | 板烧三件套，小食换玉米杯、饮料换无糖可乐 | **¥33.00** |

**一模一样的东西，差 ¥11，将近 25%。**

所以这个 Skill 拿到菜单后，第一个动作不是枚举单品，而是**扫出全部套餐、按折扣排序**，然后对每档方案做三线比价：

| 线 | 含义 |
|---|---|
| **A 套餐原样** | 直接点，默认搭配 |
| **B 套餐换项** | 换掉不需要的项（有时换项反而**倒找钱**，实测换小杯玉米杯 −¥1.50）|
| **C 单品单点 / 套餐+单品** | 只要其中一两样，或套餐打底再补单品 |

**套餐优先，但不代表套餐永远赢。** 只想要"汉堡 + 水"时，单点 ¥31 就比三件套 ¥33 便宜——它会算，不会硬推套餐。

> 这一条是被用户追问"没有什么很值的套餐选择吗"之后才补上的。之前确实漏了，记在 `references/pitfalls.md` 第 23 条。

## 这个 Skill 的立场

**不劝你多买，不给你算错的数，也不给你编故事。**

三条明确取舍：

**① 凑单检测会告诉你"别凑"。**
如果加了 ¥10 一份小食只换来 ¥5 减免——它会直接说：

> ⚠️ 凑单陷阱：净多花 ¥5.00 换一份玉米杯，这不是省钱，是多吃。

市面上大部分"省钱助手"只教你怎么凑，很少教你不该凑。

**② 热量查不到就说查不到，绝不估算。**
实测套餐热量如果直接按名字查，会**低估近一半**：麦辣鸡腿堡三件套查出来 485 kcal，真实值是 **921 kcal**。给减脂的人这个数，等于让他一顿吃两顿的量。

**③ 节日不承诺麦当劳没有的东西。**
生日没有蛋糕和蜡烛，中秋没有月饼，玩具随机不可指定。**这些一律直说，并给替代方案**（如用圆筒冰淇淋插薯条当蜡烛）。

用户照方案到店发现没有，白跑一趟——比不给方案更糟。

所以这个 Skill 对套餐一律拆 round 逐项累加，查不到的（48.7% 的餐品）明确标注"官方未收录"，不拿同类餐品凑数。

## 安装

**前置条件**：麦当劳 MCP Token（免费）

1. 打开 [open.mcd.cn/mcp](https://open.mcd.cn/mcp)，右上角【登录】，手机号验证登录
2. 点【控制台】→【激活】→ 同意服务协议 → 复制 Token
3. 在 WorkBuddy 的「管理连接器」→「自定义配置」中填入：

```
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

把 `${MCD_MCP_TOKEN}` 换成你自己的 Token，保存后**手动打开启用开关**。

4. 把 `SKILL.md` 及 `references/` 放入 WorkBuddy 技能目录（`~/.workbuddy/skills/mcd-meal-planner/`）

**配置完成后**，在对话里说"帮我看看怎么点最便宜"即可触发。

## 使用示例

### 例 1：套餐推荐

> **你**：今天麦当劳吃什么？随便推荐一个
>
> **它**：现在（20:10）是夜市，这家店 110 个单品，给你 3 个不同风格：
>
> **① 经典稳健｜麦辣鸡腿汉堡三件套** ¥47 → **¥33.50**
> 👉 招牌款，三件套比单点省 ¥13.5。小食换小杯玉米杯能更便宜（实测 −¥0.5，随门店变化）。
>
> **② 超值省心｜随心配 1+1**
> 👉 这个价位能吃到主食 + 饮品。
>
> **③ 尝鲜解锁｜龙焰芝士棒鸡腿堡三件套**
> 👉 本周上新，当季限定。

### 例 2：麦门省钱 + 凑单陷阱

> **你**：一个汉堡加杯可乐，怎么点最便宜？
>
> **它**：
>
> | 档位 | 组合 | 原价 | 用券后 | 省 |
> |---|---|---|---|---|
> | 最省 | 双层吉士汉堡 + 无糖可乐中杯 | ¥15 | **¥15.00** | ¥0 |
> | ⭐最均衡 | 麦辣三件套（小食换小杯玉米杯） | ¥47 | **¥32.00** | ¥15 |
> | 最满足 | 巨无霸 + 中薯条 + 可乐中杯 | ¥xx | **¥xx** | ¥xx |
>
> 省钱要点：关键是用「11.9元麦辣鸡腿堡」券，省 ¥xx。
>
> ⚠️ **凑单陷阱**：再加 ¥x 能跨「满 ¥40 减 ¥5」，但净多花 ¥x——这不是省钱，是多吃一份。不建议。

### 例 3：聚餐一键点

> **你**：4 个人吃麦当劳，预算 160，有人不吃辣
>
> **它**：主食按 4 份配（每人一份，没有 +1 凑数），小食用了 20 块分享装（单价更低）。合计 ¥105.00，人均 ¥26.25，预算内还剩 ¥55。要不要加份甜点？

### 例 4：控卡配餐（热量要真算得对）

> **你**：我在减脂，600 大卡以内，不要辣
>
> **它**：
>
> | 餐品 | 热量 | 蛋白 | 钠 | 价格 |
> |---|---|---|---|---|
> | 板烧鸡腿堡 | 391 kcal | 23g | 1041mg | ¥23.50 |
> | 小杯玉米杯 | 53 kcal | 2g | 1mg | ¥13.00 |
> | 无糖可口可乐中杯 | 0 kcal | 0g | 35mg | ¥9.50 |
>
> 合计 **444 kcal**｜蛋白 **25g**｜**¥46.00**
>
> **一个更划算的换法**：本来想点中薯条（289 kcal），换小杯玉米杯——省 236 kcal、省 164mg 钠，**还便宜 ¥0.50**。
>
> ⚠️ 龙焰鸡腿堡、蓝莓爆爆珠麦旋风等新品**官方未收录营养数据**，没法算，已排除。

### 例 5：活动 + 券的"现在能不能用"

> **你**：最近有什么活动？
>
> **它**：
>
> **🍔 新品值得试**：龙焰鸡腿堡三件套 ¥26.9（原价 ¥47.5），本周上新
> **🎁 周边加购**：GD 联名棒球帽/徽章/丝巾，消费**加 ¥39.9** 可得
> **⏰ 即将生效**：「11.9 元麦辣鸡腿堡」10/26 起，**仅周一至周五**。今天周六，**用不了**
>
> 把今天用不了的优惠当成今天能省的，是这个场景最容易犯的错。

### 例 6：节日搭配

> **你**：情人节两个人吃，怎么点比较好
>
> **它**：
>
> | 餐品 | 数量 | 单价 | 为什么选它 |
> |---|---|---|---|
> | "我就喜欢"鸡薯双全盒 | 1 | ¥15.90 | 名字就是表白 |
> | 心形薯饼 8 块 | 1 | ¥9.90 | 有心形，限时特惠（原价 ¥22.50）|
> | 龙焰鸡腿堡 | 2 | ¥15.90 | 主食成对（原价 ¥24，促销中）|
> | 蓝莓爆爆珠麦旋风 | 2 | ¥16.50 | 紫色，拍照好看 |
> | 可乐中杯 | 2 | ¥9.50 | |
>
> 原价 ¥138.40 → 实付 **¥109.60**（省 ¥28.80）｜人均 **¥54.80**
>
> ⚠️ 这 ¥28.80 全来自两项促销，活动结束会恢复原价。
>
> **如果问"生日能配蛋糕吗"——它会直说麦当劳没有蛋糕和蜡烛，建议用圆筒冰淇淋插薯条代替。**

## 技术架构

没有后端，没有数据库，本地只有一个求解脚本。

```
用户对话
   │
   ▼
WorkBuddy（Agent）
   │
   ├── SKILL.md ─────── 场景路由 / 调用顺序 / 23 条铁律
   │
   ├── 麦当劳 MCP Server (mcp.mcd.cn)
   │      Streamable HTTP + Bearer Token
   │      ├── 时间 / 门店 / 菜单 / 套餐详情
   │      ├── 券 / 促销 / 算价
   │      ├── 营养表（TOON 格式）
   │      └── 下单（需用户确认）
   │
   ├── combo_solver.py ── 本地组合求解 + 凑单陷阱检测
   └── nutrition_helper.py ── 热量安全匹配 + 套餐拆轮 + 控卡求解
```

**为什么需要本地脚本？**

不是所有组合都该丢给远程算价。接口限流 600 次/分钟，全量枚举会打光额度。`combo_solver.py` 先在本地把 1210 个组合筛成 Top 3，只对候选调 `calculate-price`。

`nutrition_helper.py` 解决的是另一个问题：**接口返回的营养数据不能直接信**。它挡掉两类错误——套餐被模糊匹配成单品（低估 47%）、引号不一致导致有数据也匹配不到。

**实测效果：1210 个组合本地算完，远程调用 0 次。**

## 已知约束

| 约束 | 说明 |
|---|---|
| 门店每次只返 5 家 | 地址需给到商圈级别 |
| 套餐替换限同一轮 | 必须查 `query-meal-detail` 看真实选项 |
| 套餐换项价必须真算 | 换项会同时改价格和热量，两边都要重算 |
| **营养表只有 51.3% 覆盖** | 套餐/新品/周边无数据，只能标注"未收录"，不估算 |
| **套餐热量必须拆轮** | 直接按名字查会低估 47% |
| 券常有"未生效"状态 | 推荐前必须比对生效日/截止日/星期/时段 |
| `query-promotions` 仅团餐可用 | 到店场景用 `query-store-coupons` |
| **麦当劳没有生日蛋糕/月饼** | 节日推荐不能承诺这些，给替代方案 |
| 限流 600 次/分钟 | 已用本地求解器把算价从 1210 次压到 3 次 |
