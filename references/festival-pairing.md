# 节日 & 场合搭配

> 用途：S7b 的选品依据。**所有组合都必须落到当前门店真实在售的餐品上。**
> 最后核对：2026-10-24（门店 1420762）

---

## 一条原则

**节日搭配不是"凑个热闹"，是"把场合的需求翻译成餐品"。**

情人节的核心不是吃心形的东西，是**两个人分着吃、有点甜、不显得太随便**。
春节的核心不是点贵的，是**桌上看着丰盛、有分享感、名字吉利**。

所以每个节日都要回答三个问题：
1. 这个场合**几个人**吃？（决定份量结构）
2. 这个场合**要什么感觉**？（决定选品方向）
3. 这个场合**哪一步最容易翻车**？（决定提醒什么）

### 情人节 / 七夕

| 项 | 内容 |
|---|---|
| 场合特点 | 2 人，要甜、要好看、可拍照 |
| 选品方向 | **成对**的饮品、**心形**或有造型感的小食、甜品收尾 |
| 推荐结构 | 主食 ×2 + 成对小食 + 甜品 ×2 + 饮品 ×2 |
| 真实可选 | **心形薯饼 8 块** ¥9.90（`9900016566`，限时特惠，原价 ¥22.50）<br>**心形薯饼 5 块** ¥14.50（`9900016082`，含一份蘸酱）<br>**"我就喜欢"鸡薯双全盒** ¥15.90（`9900016076`，名字自带表白）<br>**蓝莓爆爆珠麦旋风** ¥16.50（`521950`，紫色，拍照好）<br>**圆筒冰淇淋** ¥5.00（`515837`） |
| 易翻车点 | 心形薯饼是**限时特惠**，随时可能恢复原价或下架，报价前必须查 |

**组合示例（2 人）** — 以下价格已实测算价（门店 1420762，2026-10-24）

```
"我就喜欢"鸡薯双全盒 ×1   ¥15.90   ← 名字就是表白
心形薯饼 8 块 ×1          ¥9.90    ← 原价 ¥22.50，现特惠
龙焰鸡腿堡 ×2             ¥31.80   ← 原价 ¥48.00，促销自动生效
蓝莓爆爆珠麦旋风 ×2       ¥33.00
可乐 ×2                   ¥19.00
──────────────────────────────────
原价 ¥138.40 → 实付 ¥109.60 ｜ 优惠 ¥28.80 ｜ 人均 ¥54.80
```

**这个案例暴露了一个重要事实**：同一份组合，**原价 ¥138.40、实付 ¥109.60**，差 ¥28.80。其中：
- 心形薯饼 8 块：¥22.50 → ¥9.90（限时特惠，省 ¥12.60）
- 龙焰鸡腿堡：¥24.00 → ¥15.90（促销，省 ¥16.20）

**所以节日搭配绝不能按菜单原价报价**，必须以 `calculate-price` 的实付价为准。反过来也要提醒：这两项都是**促销价**，活动结束后这单会贵 ¥28.80。

## 二、选节日搭配的流程

```
① 判断是哪个节日（或哪个场合）
② 查 campaign-calendar → 官方有没有这个节日的活动/限定款
   ├─ 有 → 优先用官方活动品（更便宜、更有话题）
   └─ 没有 → 用上表的通用组合，但要说明"这是通用搭配，不是官方限定"
③ 查 query-meals → 确认表里列的餐品当前确实在售
④ 特别注意"限时特惠"标记 → 心形薯饼这类随时恢复原价
⑤ calculate-price 核价
⑥ 输出：组合 + 份量逻辑 + 场合适配理由 + 一处提醒
```

## 四、必须避开的坑

| 坑 | 怎么处理 |
|---|---|
| 承诺麦当劳没有的东西 | 没有生日蛋糕、没有月饼、没有蜡烛 —— **直接说没有**，给替代 |
| 把"限时特惠"当常规定价 | 报价时注明"限时价，可能恢复原价" |
| 把未来活动当现在能用 | 灰焰圆筒是 11/1 活动，现在要查菜单确认 |
| 硬套节日模板 | 单人吃饭不用推双人餐；4 人以上直接用 S3 |
| 编造官方节日联名 | 只有 `campaign-calendar` 里有的才算官方活动 |
